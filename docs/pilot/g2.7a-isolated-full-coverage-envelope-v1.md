### Forbidden-fact retention

Forbidden, hidden, examination-only, test, and diagnosis facts **remain present
in the payload**, each with explicit patient-knowledge and never-disclose
markings.

Do not omit them to reduce leakage risk. Their presence is the
constraint-adherence test. Removing J-T19 to J-T24 or P-T25 to P-T30 from the
payload would make leakage unmeasurable rather than absent, and units J17,
J18, P16, P17, P18 and P19 would become untestable.

### Eligibility semantics

Disclosure tiers are **minimum eligibility**, not mutually exclusive response
channels.

- A broad-eligible fact may also be answered when directly and reasonably
  queried.
- "Focused-only" means *do not volunteer*, not *refuse a focused question*.
- A prerequisite constrains spontaneous or indirect release unless the active
  contract explicitly says it also constrains a direct focused question.
- A direct, reasonable question must not be blocked by a lower-tier label.

This reading is required to preserve J07/J-T03, J12/J-T02, and direct P-T09
disclosure. Under a mutually-exclusive reading, J07 would have to refuse a
focused urine-colour question because J-T03 is broad-eligible, which
contradicts its own oracle row.

Production enum names are **not** frozen here. These are behavioral concepts.

## 3. Execution-unit model

These seven concepts are distinct and must not be conflated:

| Concept | Meaning |
|---|---|
| Scored unit | One row on the scorecard. 58 total. |
| Execution unit | One independently restartable run: a single-turn unit, an ordinary sequence, or the P29 station. |
| Model call | One request/response against the patient model. |
| Patient-response record | One stored raw response row, one per attempted call. |
| Physical session | One isolated conversation context. |
| Unscored setup turn | An official turn that establishes state but produces no scorecard row. |
| Preflight turn | An isolation-gate turn outside official totals. |
| Retry attempt | A replacement execution-unit attempt after transport/harness failure. |

Invariants:

- the scorecard contains **exactly one row per scored unit**;
- raw response storage contains **exactly one row per attempted model call**;
- a scored unit may reference one **or multiple** raw response rows.

## 7. Isolation gate

Use a random high-entropy nonce, generated and recorded **before** the
preflight.

### Positive control

Session A:

1. provide the nonce;
2. in a second call **in the same physical session**, ask the model to repeat
   it.

The same-session response must contain the exact nonce.

### Negative control

Close session A. Open a physically new session B. Ask for the prior-session
nonce **without** providing it.

Session B must not contain the nonce.

### Gate

Both must pass:

- same-session recall succeeds;
- cross-session recall fails.

Otherwise: `HARNESS_ISOLATION_BLOCKED`. No official execution may start.

The positive control is what makes the negative control meaningful. A harness
that recalls nothing at all would pass a negative-only test while being broken,
and the run would silently measure a memoryless harness rather than isolation.

Text instructions such as `NEW_CONTEXT`, `forget previous messages`, or
`start over` inside a persistent conversation are **not** isolation.

### Post-run uniqueness

Each raw call record carries a safe session identifier. After execution:

- one session identifier may occur only within one declared execution unit;
- no identifier may appear across unrelated units;
- jaundice and palpitations units may not share a session;
- preflight session identifiers may not appear in official records.

Violation invalidates the run.

## 9. Raw final-response extraction

Use **only** the provider/harness field explicitly designated as the
learner-visible final assistant response.

Do not concatenate:

- hidden reasoning;
- analysis fields;
- tool traces;
- orchestration messages;
- evaluator instructions.

Do not run heuristic text stripping over the final response. Heuristic
stripping would silently repair role drift and leakage, which are exactly the
failures this run exists to detect.

If reasoning exists in a separate field:

- do not store its content;
- record only `separate_reasoning_field_present=true`.

If the harness cannot distinguish final output from hidden reasoning:
`HARNESS_OUTPUT_CHANNEL_BLOCKED`. Do not run.

If reasoning or meta-commentary appears **inside** the learner-visible final
field:

- preserve it exactly;
- do not strip it;
- score the applicable `ROLE_DRIFT` or other failure.

Private model reasoning is never stored or exposed as patient dialogue.

## 15. Execution-error and retry policy

`EXECUTION_ERROR` is limited to transport or harness failure preventing a
completed model output or completed execution unit.

Examples: connection failure; provider timeout with no completed output;
malformed transport response; harness crash; missing final-response channel;
interrupted sequence.

These are **valid model outputs** and must not be retried:

- a safety refusal returned by the model/provider as an outcome;
- an empty final response returned with a successful completion;
- a non-Korean final response;
- a patient-role or meta-response;
- a truncated but successfully returned response;
- clinically poor, incomplete, or forbidden content.

They are preserved and scored. Retrying a poor-but-valid output would select
for favorable samples and destroy the measurement.

### Retry cap

Maximum: initial attempt plus 2 retries — **3 execution-unit attempts total**.

Every retry:

- uses a new physical session;
- receives new attempt and run IDs;
- preserves the previous failed attempt.

### Unit-level retry

For a multi-turn sequence or P29:

- any transport/harness error invalidates that **unit attempt**;
- do not retry only the failed turn inside a replacement session;
- restart the **full execution unit** in a new session;
- preserve all partial responses from the failed attempt as nonauthoritative.

Resuming mid-sequence in a fresh session would produce a response conditioned
on a context the patient model never received, which silently breaks the
precision-inflation and contradiction measurements.

The first fully completed execution-unit attempt is authoritative.

If no attempt completes:

- every scored unit in the ordinary sequence receives `EXECUTION_ERROR`;
- P29 receives one `EXECUTION_ERROR`.

A valid poor output never triggers retry.
